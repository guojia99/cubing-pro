# 后续维护事项

本次整理保留既有包路径、业务接口和初始化行为。以下事项有独立的运行或数据兼容影响，没有混入结构拆分。

## 已跟踪的证书与私钥

`build/bot.crt`、`build/bot.key` 仍有本地 QQ webhook 配置引用，不能在没有替代文件的情况下直接删除。它们不应作为共享开发凭据。维护者需在实际部署环境完成：

1. 确认使用范围，生成或签发替代证书，并轮换曾使用过的私钥。
2. 将新文件放在仓库外，限制读取权限，更新私人配置中的 `robot.QQBot[].server.certFile`、`certKey`。
3. 验证需要的机器人实例后，从版本库移除旧文件；历史清理涉及已有克隆和分支，应单独协调。仅删除当前版本不能撤销历史暴露。

本轮没有输出凭据内容、修改私人配置、轮换证书或重写 Git 历史。

## 初始化和测试隔离

- `wca_api` 的 Seniors 缓存在包级 `init()` 中启动后台刷新，导入即可联网、写缓存；显式生命周期改造会改变启动时点，需单独验证。
- `NewConvenient` 保留原有逐次 AutoMigrate 及忽略错误的策略；`DB()` 对应字段未赋值的现状未改。
- `cmd/initer` 注册子命令时捕获服务指针的方式存在空指针风险，应在独立修复中覆盖真实命令执行。
- JWT 密钥、管理员默认密码、整对象启动日志和 WCA 同步命令的凭据传递需要独立处理；密钥轮换及登录态影响不能作为纯结构变更。
- 默认测试集应逐步隔离真实数据库、网络、文件生成与同步维护操作；在此之前按[开发指南](development.md)选择包，不能默认执行全量测试。
